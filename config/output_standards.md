# ========================================================
# 全局输出规范
# EcoPolicy Output Standards
# ========================================================
# 本文档定义了系统所有产出文档的格式、排版和命名规范。
# 所有 .md 文件必须遵循本规范。
# ========================================================

---

## 一、文件格式

### 1.1 主格式：Markdown (.md)

| 规范 | 要求 |
|:--|:--|
| 编码 | UTF-8 |
| 字符集 | 纯 ASCII + CJK（中文/日文/韩文） |
| 禁用字符 | emoji（）、box-drawing（）、数学符号（<= >=）、箭头（-> ^） |
| 替代方案 | emoji -> [文字标签]，箭头 -> 文字描述或 ASCII |
| 行尾 | LF（n） |

### 1.2 分享格式：HTML (.html)

- 用途：分享给未安装 Markdown 阅读器的人员
- 特点：零依赖（mermaid.js CDN 除外）、A4 排版、浏览器双击即开
- 生成工具：`md_to_html.py`

## 二、文档结构

### 2.1 标准结构

每份政策分析报告必须包含以下结构：

```
---
YAML Frontmatter（文档元数据）
---

# 报告标题

> 一句话判断（30字内的核心结论）

## 目录

---

## 一、[章节名]

### 1.1 [小节]

内容...

---

## 二、[章节名]

...

---

> 结论：一段话总结 + 行动建议
```

### 2.2 YAML Frontmatter 必填字段

```yaml
---
title: "报告完整标题"
date: "YYYY-MM-DD"
author: "AI 助手名称"
status: "初稿"   # 初稿/审核/定稿
tags: ["关键词1", "关键词2", "关键词3"]
---
```

### 2.3 一句话判断

位于标题下方第一个元素，用引用块格式：

```
> **一句话判断**：[30字内的核心结论，让用户30秒内决定是否继续阅读]
```

### 2.4 目录

使用标准 Markdown 锚点链接：

```
## 目录

1. [政策速览](#一政策速览)
2. [匹配度评估](#二匹配度评估)
3. [行动建议](#三行动建议)
```

## 三、排版规范

### 3.1 章节层级

| 层级 | 语法 | 用途 |
|:--|:--|:--|
| 一级标题 | `#` | 报告标题（全文仅一个） |
| 二级标题 | `##` | 大章节（一、二、三...） |
| 三级标题 | `###` | 小节（1.1, 1.2...） |
| 四级标题 | `####` | 子项（仅在必要时使用） |

### 3.2 分隔线

- 大章节之间使用 `---` 水平分隔线
- 小节之间不加分隔线
- 文档末尾结论前加分隔线

### 3.3 表格

**对齐规则**：

```
| 左对齐 | 居中 | 右对齐 |
|:--|:--:|--:|
| 文本 | 状态 | 数字 |
```

**列数限制**：A4 竖版不超过 5 列

**表头格式**：表头行必须加粗关键字

### 3.4 引用块

用于结论、警告、重要提示：

```
> **结论**：一段话总结。

> **注意**：此政策有XX风险。

> **关键信息**：申报截止日期为XX。
```

### 3.5 Obsidian Callout（可选）

在 Obsidian 环境中使用彩色标注块，其他阅读器降级为普通引用：

```
> [!IMPORTANT] 关键判断
> 这是最重要的信息。

> [!WARNING] 风险提示
> 这里有风险需要注意。

> [!TIP] 操作建议
> 建议这样做。

> [!NOTE] 补充说明
> 额外背景信息。
```

### 3.6 代码块

用于流程对比、公式、命令示例：

````
```
旧模式：A -> B -> C
新模式：X -> Y -> Z
```
````

## 四、评分体系

### 4.1 匹配度评分（5/5 分制）

| 评分 | 标签 | 含义 |
|:--|:--|:--|
| 5/5分 | 首选推荐 | 完美匹配，立即行动 |
| 4/5分 | 强烈推荐 | 高度匹配，优先推进 |
| 3/5分 | 推荐 | 部分匹配，条件具备时可参与 |

### 4.2 排序标签

| 标签 | 含义 |
|:--|:--|
| [1st] | 第一优先 |
| [2nd] | 第二优先 |
| [3rd] | 第三优先 |

### 4.3 紧迫度标签（P0/P1/P2）

| 标签 | 时限 | 含义 |
|:--|:--|:--|
| P0 | 本周内 | 紧急，不行动则错过窗口 |
| P1 | 2-4周 | 重要，有缓冲但需推进 |
| P2 | 持续 | 长期关注，不紧急 |

## 五、图表规范

### 5.1 图表类型

| 类型 | 语法 | 适用场景 |
|:--|:--|:--|
| 流程图 | `mermaid flowchart` | 决策树、机制对比、策略架构 |
| 甘特图 | `mermaid gantt` | 时间轴、阶段规划 |
| 表格 | Markdown table | 数据对比、清单 |

### 5.2 mermaid 图表 A4 适配规则

| 规则 | 要求 |
|:--|:--|
| 字体大小 | 流程图 11-13px，甘特图 9-11px |
| 标签长度 | 甘特图任务标签控制在 5-7 个汉字 |
| 流程图方向 | 优先 LR（横向），避免深度嵌套 |
| 甘特图独立分页 | 宽度超 A4 内容区的甘特图，前后加 `---` 独立分页 |
| 节点数量 | 单图不超过 15 个节点 |

### 5.3 mermaid 初始化模板

```markdown
%%{init: {
  'theme': 'base',
  'themeVariables': {
    'fontSize': '11px',
    'primaryColor': '#E8F5E9',
    'primaryBorderColor': '#2E7D32',
    'primaryTextColor': '#1B5E20',
    'lineColor': '#43A047'
  }
}}%%
```

## 六、文件命名规范

### 6.1 命名规则

```
{描述}_{YYYY-MM-DD}.{扩展名}
```

示例：
- `policy_analysis_2026-05-18_拨改投试点.md`
- `exit_path_design_2026-05-18.md`
- `application_form_filling_guide_2026-05-18.md`

### 6.2 文件夹结构

```
{企业简称}/                          ← 项目根目录
├── CLAUDE.md                          AI 助手说明书
├── PROJECT_CONTEXT.md                 项目记忆
├── company_profile.txt                公司画像
│
├── config/                             系统框架文件
│   ├── company_profile_template.yaml  企业画像模板
│   ├── policy_matrix_generator.md     分析框架
│   └── output_standards.md            输出规范
│
└── {政策项目名}/                       每个政策项目一个子文件夹
    ├── policy_analysis_*.md           政策分析报告
    ├── exit_path_design_*.md          退出路径方案
    ├── application_guide_*.md         申报书填报指南
    └── {其他专项报告}.md
```

### 6.3 目录管理规则

| 规则 | 说明 |
|:--|:--|
| 根目录只放基础资料 | 公司画像、AI配置、项目记忆 |
| 生成文件归入子文件夹 | 每个政策项目一个文件夹 |
| 同一政策的所有产出放同一文件夹 | 方便查阅和分享 |

## 七、禁忌清单

以下内容在任何产出中禁止出现：

| 类别 | 禁止内容 | 替代方案 |
|:--|:--|:--|
| emoji | 星星、勾、箭头等所有 emoji | [文字标签] |
| box-drawing | 时间轴线、框架线 | ASCII 纯文本 |
| 星号残留 | 原文中的 `**粗体**` 未被渲染 | 确保 Markdown 渲染器正确解析 |
| 灰色背景块 | code block 作为文本容器 | 使用引用块或列表 |
| 主观臆测 | 无依据的判断 | 标注"待确认"或"需进一步核实" |
| 法律断言 | "这一定可以"/"肯定能通过" | "根据政策文本，具备申报条件" |
